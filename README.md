# Experiment 1 - Measuring Performance

This repository contains the code and raw data of an experiment comparing the
execution time of three Bubble Sort implementations (`BubbleSortPassPerItem`,
`BubbleSortUntilNoChange`, `BubbleSortWhileNeeded`), in order to recommend
the fastest one for inclusion in the Bubble Inc. Java utility library.

## Requirements
- Java 25 (experiment run with Java 25.0.2)

## How to run
From the `src` folder:

```bash
javac -d ../out exp01/*.java && 
java -cp ../out exp01.ExperimentRunner
```

For reliable measurements, run the experiment with the computer connected to
power, low power mode disabled, and all other applications closed.


> **Warning:** running the experiment overwrites `data/results.csv`.

## Output
The program writes `data/results.csv`, one row per measurement:

| Column | Meaning |
|---|---|
| `algorithm` | Sorting algorithm measured |
| `arrangement` | Initial order of the input: `SORTED`, `REVERSED`, `RANDOM`, `NEARLY_SORTED` |
| `size` | Number of elements in the array (1000, 5000, 10000, 20000) |
| `repetition` | Index of the repetition (0–29) |
| `time_ns` | Execution time of one call to `sort()`, in nanoseconds |

## Data
- `data/results.csv`: raw data of the final run used in the report
  (1440 measurements: 3 algorithms × 4 arrangements × 4 sizes × 30 repetitions).
- `data/pilot_results.csv`: raw data of a pilot run performed with other
  applications open, kept for transparency.

## Experimental setup
- Machine: MacBook Pro 14" (2023), Apple M3 Pro (11 cores), 18 GB RAM, macOS 27.0.1
- Input arrays are permutations of the integers 1..n (`Integer[]`),
  generated by `InputGenerator`. `NEARLY_SORTED` arrays are obtained by
  performing n/100 swaps between random positions of a sorted array.
- 30 repetitions per condition; repetition r uses seed `42 + r`, so all
  algorithms sort the same arrays.
- The execution order of all measurements is randomized (seed `2026`).
- Before measuring, each algorithm is run 20 times on a random array of
  1000 elements (warm-up), and these timings are discarded.
- Each measurement sorts a fresh copy of the input array; the result is
  checked to be sorted (outside the timed region).
- All parameters are defined as constants in `ExperimentRunner.java`.
